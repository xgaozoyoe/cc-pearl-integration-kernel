Interpretation:
1. Sustained Tensor activity is a real differentiator in this comparison, not
merely GPU utilization. Peak nearly continuously active;Open main workload also
has Tensor stalls/underuse even whenSMs are active. Host gaps alone do not explain it.
2. Higher SM Issue/warps occupancy is not the optimization target:Open reports
more of both while delivering less Tensor activity and throughput. SM Issue is
issuing-cycle fraction,not useful arithmetic utilization or instruction/MMA count.
3. Off-chip DRAM is not near peak on either GPU. This does NOT rule out L2/shared
traffic or latency bottlenecks; those aren't measured in this capture.
4. This does NOT identify Peak MMA type/shape,count,precision,sparsity,CTA mapping,
register allocation or exact barrier scheme. No causal speedup claim can be made
from the activity ratio alone, and no binary protection bypass is attempted.

Next research:use sustained Tensor duty cycle as an acceptance metric alongside
full-grid TH/s and correctness;analyze main-loop MMA/address/load/control issue
budget,then design a materially different schedule. Stop prioritizing tiny
bounds/slot rewrites and occupancy alone. No new production code changes this turn.
